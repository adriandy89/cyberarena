# Plataforma de aprendizaje de ciberseguridad estilo TryHackMe — Plan Maestro SDD

## 1. Visión y decisiones confirmadas

Plataforma personal **bilingüe ES/EN**, **multi-usuario con roles** (admin/estudiante), con catálogo de rooms estilo hacktivities, sistema de progreso gamificado, labs prácticos con **Docker Compose por room**, y **todo el despliegue en Docker con stacks separados por carpetas y hardening de seguridad**. Desarrollo profesional con **metodología SDD** (Spec-Driven Development) y resistencia total a reinicios de conversación.

Recorrido de contenido (novato → experto, sin empezar de lo más básico): **Cyber Security 101 → Jr Penetration Tester → Web Application Pentesting → Web Application Red Teaming → Red Teaming (nivel PT2)** — según el roadmap de carrera de la captura que enviaste.

## 4. Modelo de contenido (content-as-code)

- Jerarquía THM: **Path → Módulo → Room → Task → Preguntas/flags** (`FLAG{...}` propio, formato THM-like).
- Rooms en MDX con frontmatter validado por Zod en build: slug estable, título, descripción, dificultad (Info/Easy/Medium/Hard/Insane), tipo (walkthrough/challenge/capstone), tiempo estimado, categorías/tags, lab opcional (`lab: <room-slug>` → labs/), soporte i18n.
- **Las respuestas nunca viajan al cliente**: questions en MDX (enunciado + hint), answers en `packages/content/private/` → seed a BD con hash; la API solo valida (comparación normalizada case/trim-insensitive).
- Labs: cada `labs/<room-slug>/compose.yaml` levanta máquinas vulnerables autocontenidas (patrón Vulhub), red interna aislada, efímeras (`docker compose up -d` desde el room), flags inyectadas por variables de entorno al crear el contenedor.

## 5. Sistema de progreso y gamificación

- **XP** por pregunta correcta (walkthrough 10 / challenge 30 / capstone 40, definido en `packages/shared`), evento XP inmutable (XpEvent), bonus primera intent.
- **Progreso**: % por room (preguntas completadas), agregado a módulo y path; bloqueo opcional secuencial de rooms por módulo.
- **Niveles** con umbrales crecientes (21 rangos estilo THM: Neophyte→Grandmaster, adaptado), mostrados en perfil.
- **Streaks** diarias (mín. 3 preguntas/día, medianoche local, streak-freezes), **badges** (streaks, módulo completado, path completado, first-blood), **leaderboard** (mensual/all-time), **certificado** por path completado (HTML/PDF descargable) y **skill matrix** por categorías.
- Modelo de datos Prisma (resumen): User/Session/Account (Better Auth) · Path · Module · Room · Task · Question · RoomProgress · QuestionAttempt · XpEvent · Badge · UserBadge · Streak · Certificate (+ LabSession en fase labs).

## 6. Docker y seguridad (requisito explícito)

- **Dev**: `infra/stacks/dev` — un comando levanta todo (postgres, api, web con volúmenes/hot-reload, mailpit para emails de auth).
- **Prod**: `infra/stacks/prod` + `infra/stacks/proxy` (Caddy con HTTPS automático ACME, red externa compartida, headers de seguridad).
- **Hardening** (checklist OWASP Docker): usuarios no-root numéricos en todas las imágenes, `cap_drop: ALL`, healthchecks en cada servicio, `read_only` donde aplique, imágenes mínimas (alpine/distroless) con digests fijados, secretos vía `.env` (no commiteado, `.gitignore` + `.env.example`) y `secrets:` de compose, redes segmentadas (proxy↔web↔api↔db separadas; **labs en redes aisladas sin acceso a la red de la app**), rate-limiting (NestJS Throttler), scripts de backup/restore de postgres.
- CI en GitHub Actions: lint + typecheck + tests + build + validación de contenido (content-collections) + `docker build`.

## 7. Metodología SDD y resistencia a reinicios

- Flujo por feature: **specify → clarify → plan → tasks → implement → converge**, artefactos commiteados en `specs/NNN-slug/`.
- `tasks.md` con checklist numerado (`T001 [P] [US1]`), checkpoints por fase y **commit tras cada tarea** — cualquier sesión nueva (yo u otro agente) reanuda desde el primer checkbox sin marcar, leyendo `AGENTS.md` + `specs/` + `docs/adr/`.
- `constitution.md` con los principios no negociables (seguridad first, docs actualizadas siempre, content-as-code, tests en lógica de negocio, commits atómicos).
- Además guardaré memoria persistente del proyecto (estado, decisiones, siguiente tarea) para acelerar futuras sesiones.
